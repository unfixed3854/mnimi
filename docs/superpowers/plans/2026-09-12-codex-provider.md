# Codex Subscription Provider Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an operator-authenticated Codex provider for every mnimi text and image generation path while retaining the existing OpenRouter provider.

**Architecture:** Server startup selects one atomic `AiProvider` bundle and injects its text and image capabilities into HTTP handlers and durable schedulers. The Codex bundle owns one restartable, pinned `codex app-server` stdio process; each operation gets a fresh ephemeral thread and least-privilege temporary workspace, while the OpenRouter bundle preserves current behavior.

**Tech Stack:** Bun 1.3.13, TypeScript 6.0.3, Vitest 4.1.10, Zod 4.4.3, official `@openai/codex` 0.154.0, Codex app-server JSON-RPC/JSONL, Hono, oRPC

**Spec:** `docs/superpowers/specs/2026-09-12-codex-provider-design.md`

## Global Constraints

- Use Bun for dependency management and every project or test command.
- Run the full suite with `bun run test`; do not replace it with raw `bun test`.
- Pin `@openai/codex` to exactly `0.154.0`; upgrades require the protocol contract test to pass.
- `AI_PROVIDER` accepts only `openrouter` or `codex` and defaults to `openrouter`.
- Provider selection is atomic: Codex mode must never import, initialize, call, or fall back to OpenRouter.
- Both providers use `CLASSIFY_MODEL`, `CLASSIFY_EFFORT`, `GENERATE_MODEL`, and `GENERATE_EFFORT`; `IMAGE_MODEL` remains OpenRouter-only.
- Codex defaults are `gpt-5.6-luna`/`low` for classify-role work and `gpt-5.6-sol`/`high` for generate-role work.
- Codex mode requires ChatGPT-managed authentication and must remove `OPENAI_API_KEY` from the child environment.
- Codex mode rejects `REGISTRATION_ENABLED=true` before binding HTTP or starting schedulers.
- Use one long-lived app-server child per Bun server process, with a fresh ephemeral thread and temporary workspace per operation.
- Model-run commands may read only platform/runtime essentials, may write only the operation workspace, and have command network disabled.
- Never log raw JSON-RPC messages, prompts, output, tokens, account email, or app-server stderr content.
- Never grant command, file, network, filesystem, user-input, or MCP elicitation requests from app-server.
- A failed or disconnected operation is never replayed and never crosses providers; only a later operation may start a replacement app-server process.
- Preserve the current job-cancellation contract: late provider results are ignored by the job layer, but accepted upstream work is not automatically cancelled.
- Normal automated tests are offline and must not require login or consume Codex allowance.
- Commit commands below are proposed conventional-commit checkpoints. Under the repository's conservative policy, run them only after the user explicitly authorizes commits.

  kind: z.literal("proposed"),

  outcome: z.union([

    proposedDeckRoutingOutcomeSchema,
  ]),

export function unwrapDeckRoutingResponse(response: unknown): unknown {
  if (!response || typeof response !== "object" || !("outcome" in response)) {
    return response;
  }
  const outcome = (response as { outcome: unknown }).outcome;
  if (!outcome || typeof outcome !== "object") return outcome;
  if ((outcome as { kind?: unknown }).kind !== "proposed") return outcome;
  const { kind: _kind, ...proposal } = outcome as Record<string, unknown>;
  return { kind: "newDeck", ...proposal };
}

`ensureConnection()` starts the child, sends `initialize`, waits for its

Implement `spawnCodexAppServer(command, env)` as the only Bun-specific process
