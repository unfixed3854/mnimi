# CI Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `.github/workflows/ci.yml` so every pull request and push to `main` runs typecheck + test + frontend build (`verify`) and a Tauri Linux desktop build (`desktop-build`), in parallel.

**Architecture:** One workflow file, two independent jobs on `ubuntu-latest`, both bootstrapped via `jdx/mise-action` (Node + Deno only — no Java/Android SDK). `verify` runs `deno task build`, `deno check main.ts` in `server/`, and `deno task test`. `desktop-build` adds Rust + the Tauri Linux system packages, then runs `deno task tauri build` (which itself invokes `deno task build` for the frontend via `tauri.conf.json`'s `beforeBuildCommand`).

**Tech Stack:** GitHub Actions, `jdx/mise-action@v2`, `dtolnay/rust-toolchain@stable`, `Swatinem/rust-cache@v2`, `actions/cache@v4`, Deno 2.9.3, Node 24.15.0 (pinned in `mise.toml`).

## Global Constraints

- Do not install the `java` or `android-sdk` mise tools in any CI job — neither job builds for Android. Use `install_args: node deno` on every `mise-action` step.
- Do not use `npm`/`npx`/`yarn`/`pnpm` anywhere in the workflow — this repo's `AGENTS.md` requires `deno` for all package management and script execution.
- Every workflow file change must be validated by parsing it with `python3 -c "import yaml; yaml.safe_load(open('.github/workflows/ci.yml'))"` before committing — there is no other local syntax check available.
- Branch-protection / required-checks configuration is explicitly out of scope for this plan (repo-settings-level, per the spec).

### Task 1: Workflow skeleton, triggers, and the `verify` job

**Files:**
- Create: `.github/workflows/ci.yml`

**Interfaces:**
- Produces: a `verify` job named `verify` in `.github/workflows/ci.yml`, with no `needs:`, so Task 2 can add a sibling job that runs independently of it.

- [ ] **Step 1: Confirm the exact commands work locally before encoding them in YAML**

Run each of these from the repo root and confirm they exit 0. These are the commands Task 1's YAML will run verbatim, so any failure here means the workflow would fail too:

```bash
deno install
(cd server && deno install)
deno task build
(cd server && deno check main.ts)
deno task test
```

Expected: all five commands exit 0. (`deno task build` and `deno task test` were already confirmed working during design; this step re-confirms `deno install` and the server-side commands from a clean perspective.)

- [ ] **Step 2: Create the workflow file with triggers, concurrency, and the `verify` job**

Create `.github/workflows/ci.yml`:

```yaml
name: CI

on:
  pull_request:
  push:
    branches: [main]

concurrency:
  group: ci-${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  verify:
    name: Typecheck, test, build
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: jdx/mise-action@v2
        with:
          install_args: node deno

      - name: Install root dependencies
        run: deno install

      - name: Install server dependencies
        working-directory: server
        run: deno install

      - name: Typecheck and build frontend
        run: deno task build

      - name: Typecheck server
        working-directory: server
        run: deno check main.ts

      - name: Run tests
        run: deno task test
```

- [ ] **Step 3: Validate the YAML parses**

Run: `python3 -c "import yaml; yaml.safe_load(open('.github/workflows/ci.yml')); print('valid')"`
Expected: `valid`

- [ ] **Step 4: Commit**

```bash
git add .github/workflows/ci.yml
git commit -m "ci: add verify job (typecheck, test, build)"
```

### Task 2: Add the `desktop-build` job

**Files:**
- Modify: `.github/workflows/ci.yml` — add a second top-level job under `jobs:`

**Interfaces:**
- Consumes: nothing from Task 1's job — `desktop-build` has no `needs:` on `verify`, matching the spec's "run in parallel" requirement.
- Produces: a `desktop-build` job named `desktop-build`, independent of `verify`.

- [ ] **Step 1: Confirm the Tauri build works locally**

This machine already has the Tauri Linux system deps installed (confirmed via `pkg-config --exists webkit2gtk-4.1` and `javascriptcoregtk-4.1`, both present), so the actual build command can be verified directly rather than only trusted from documentation:

```bash
deno task tauri build
```

Expected: exits 0 and produces bundles under `src-tauri/target/release/bundle/`. This will take several minutes (full Rust release build). If it fails locally for a reason unrelated to the CI environment (e.g. a real compile error), stop and fix that first — the workflow will hit the same failure.

- [ ] **Step 2: Add the `desktop-build` job**

Add this job under the existing `jobs:` key in `.github/workflows/ci.yml`, as a sibling of `verify` (same indentation level, not nested inside it):

```yaml
  desktop-build:
    name: Tauri desktop build (Linux)
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: jdx/mise-action@v2
        with:
          install_args: node deno

      - name: Install root dependencies
        run: deno install

      - uses: dtolnay/rust-toolchain@stable

      - uses: Swatinem/rust-cache@v2
        with:
          workspaces: src-tauri

      - name: Install Tauri Linux dependencies
        run: |
          sudo apt-get update
          sudo apt-get install -y \
            libwebkit2gtk-4.1-dev \
            build-essential \
            curl \
            wget \
            file \
            libxdo-dev \
            libssl-dev \
            libayatana-appindicator3-dev \
            librsvg2-dev

      - name: Build Tauri app
        run: deno task tauri build
```

- [ ] **Step 3: Validate the YAML parses**

Run: `python3 -c "import yaml; yaml.safe_load(open('.github/workflows/ci.yml')); print('valid')"`
Expected: `valid`

- [ ] **Step 4: Confirm `verify`'s steps are untouched**

Run: `git diff .github/workflows/ci.yml`
Expected: the diff shows only new lines added after the `verify` job — no changes to `verify`'s existing steps.

### Task 3: Cache the Deno directory in both jobs

**Files:**
- Modify: `.github/workflows/ci.yml` — add one `actions/cache@v4` step to `verify` and one to `desktop-build`, immediately after each job's `mise-action` step and before any `deno install`/`deno task` step.

**Interfaces:**
- Consumes: both jobs' existing step lists from Tasks 1–2 — this task inserts a step, it does not replace any existing step.

- [ ] **Step 1: Find Deno's default cache directory**

Run: `deno info | head -5`
Expected: output includes a line like `DENO_DIR location: "/home/<user>/.cache/deno"` — confirm the path so the cache step targets the right directory. (If `DENO_DIR` is unset, Deno's default is `~/.cache/deno` on Linux; use that if the command doesn't show an override.)

- [ ] **Step 2: Add the cache step to `verify`**

In `.github/workflows/ci.yml`, insert this step in the `verify` job, right after the `jdx/mise-action@v2` step and before `Install root dependencies`:

```yaml
      - uses: actions/cache@v4
        with:
          path: ~/.cache/deno
          key: deno-${{ runner.os }}-${{ hashFiles('deno.lock', 'server/deno.lock') }}
          restore-keys: |
            deno-${{ runner.os }}-
```

- [ ] **Step 3: Add the same cache step to `desktop-build`**

Insert the identical step in the `desktop-build` job, right after its `jdx/mise-action@v2` step and before `Install root dependencies`:

```yaml
      - uses: actions/cache@v4
        with:
          path: ~/.cache/deno
          key: deno-${{ runner.os }}-${{ hashFiles('deno.lock', 'server/deno.lock') }}
          restore-keys: |
            deno-${{ runner.os }}-
```

- [ ] **Step 4: Validate the YAML parses**

Run: `python3 -c "import yaml; yaml.safe_load(open('.github/workflows/ci.yml')); print('valid')"`
Expected: `valid`

- [ ] **Step 5: Commit**

```bash
git add .github/workflows/ci.yml
git commit -m "ci: cache the Deno directory in both jobs"
```
